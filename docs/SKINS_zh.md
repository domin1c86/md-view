# 为 MdView 编写皮肤

**皮肤**是一个 JSON 文件，用来告诉 MdView 每个元素该用什么颜色、圆角有多大、字重如何。
你可以用文本编辑器写好，通过 **我的 → 导入皮肤…** 导入，它就会和内置皮肤一起出现在选择器里。

皮肤控制颜色、圆角和字重，但**不**控制布局、图标、动画、启动器图标，也不能决定界面上有哪些控件。
它无法附带字体文件，也不能引用网址 —— 参见[排版](#排版)。

---

## 最短的可用皮肤

除 `id`、`name` 和用于继承的 `base` 外，其余都是可选的。下面就是一个完整、有效的皮肤：

```json
{
  "id": "warmer-ink",
  "name": "Warmer Ink",
  "base": "ink",
  "colors": {
    "accent": "#E8A33D",
    "link": "#F0B860"
  }
}
```

没有写到的部分全部来自 `ink`。建议从这里开始，一次只覆盖一项；只有在整体替换配色时，
才需要用到下文的完整文件。

---

## 表面层级

四个表面颜色并非彼此独立，而是有次序的层级，从最靠后到最靠近读者：

```
  surfaceRaised   菜单、对话框、卡片按下时的状态
  surface         卡片、列表行、底部导航栏与侧边导航栏
  canvas          窗口本身，位于一切之后，也包括顶栏
  surfaceSunken   代码块、编辑器、下沉的填充区域
```

深色皮肤中，每一级都比下一级更亮；浅色皮肤中则更暗。两级可以取相同值 —— `Paper` 的
`surface` 和 `surfaceRaised` 都是纯白 —— 但如果次序被颠倒，所有界面都会同时显得不对劲。

顶栏刻意使用 `canvas` 而非 `surface`，这样卡片才会从背景上浮起来，而不是与之融为一体。

## 颜色令牌

全部 23 个，并标明由哪个部件绘制。

### 表面

| 令牌 | 用途 |
|---|---|
| `canvas` | 窗口背景。**也会绘制在第一帧之前**（Compose 尚未绘制时），所以此处取值不当，冷启动时会闪一下。 |
| `surface` | 卡片、底部导航栏、侧边导航栏、表格主体。 |
| `surfaceRaised` | 下拉菜单、对话框。唯一允许显得抬升的一级。 |
| `surfaceSunken` | 编辑器背景、被拦截图片的占位区、下沉填充。 |

### 强调色

| 令牌 | 用途 |
|---|---|
| `accent` | 承载皮肤个性的那一个颜色：悬浮按钮、编辑器光标、选中的标签图标、单选框、开关、分组标题、导入行。 |
| `onAccent` | 绘制在 `accent` 填充**之上**的文字与图标。需要与 `accent` 形成对比，而不是与背景。 |
| `accentSubtle` | 强调色的淡化版：选中标签的胶囊底、未保存草稿卡片、链接按下时的底色、空状态图标的光环。 |

### 文字

| 令牌 | 用途 |
|---|---|
| `textPrimary` | 正文、标题、卡片标题。 |
| `textSecondary` | 卡片摘要、列表符号、引用文字、设置项说明。 |
| `textMuted` | 最安静但仍可读的文字：时间戳、`文件名 · 2 小时前` 那一行、代码块的语言标签、图注。 |

### 线条

| 令牌 | 用途 |
|---|---|
| `border` | 卡片、代码块、皮肤缩略图周围的细线。 |
| `divider` | 设置行之间的分隔线、一级和二级标题下的横线，以及 `---` 分隔符。 |

### 文档

| 令牌 | 用途 |
|---|---|
| `link` | 链接文字。 |
| `linkPressed` | 按下时的链接文字。其背景来自 `accentSubtle`。 |
| `code` | 等宽文字，代码块和行内代码都用它。 |
| `codeBackground` | 代码块与行内代码的底色。 |
| `quoteBar` | 引用块左侧的竖线。 |
| `quoteText` | 引用块内的文字。 |
| `tableHeader` | 表格表头行的底色。 |
| `tableBorder` | 表格线：行与行之间、列与列之间，以及表格外框。 |

### 状态

| 令牌 | 用途 |
|---|---|
| `danger` | 标题栏中表示未保存的圆点、卡片提示（*只读*、*已不可用*）、导入错误。 |
| `success` | 操作成功的确认。 |
| `selection` | 文字选区。 |

## 排版

排版用**倍数表示，绝不用绝对字号**。MdView 中所有尺寸都以 `sp` 为单位，本身就会与系统的
无障碍字体缩放叠加，应用内的 **文字大小** 设置还会再乘一次。如果皮肤能把正文钉死在 11 sp，
就等于同时废掉了这两者，因此它不能这么做。

```json
"type": {
  "bodyScale": 1.0,
  "monoScale": 0.9,
  "headingWeight": 700,
  "tracking": 0.0
}
```

| 键 | 范围 | 含义 |
|---|---|---|
| `bodyScale` | 0.85 – 1.3 | 缩放正文。超出范围会被收敛，而不是被拒绝。 |
| `monoScale` | 0.7 – 1.2 | 等宽文字相对正文的大小。作用于代码块、行内代码**以及源码编辑器**。 |
| `headingWeight` | 100 – 900 | 标题和表头的字重，会被吸附到最接近的百位。 |
| `tracking` | −0.05 – 0.1 | 正文的额外字距，单位 `em`。负值收紧。 |

**没有字体族这个键。** MdView 不附带任何字体资源，也没有字体依赖；正文使用平台默认字体，
代码使用平台等宽字体。皮肤无法引用字体文件或网址。

标题的字距始终比 Material 默认值更紧，这是全局决定，不由单个皮肤控制。

## 形状

圆角半径，单位 dp，收敛到 0–48。

```json
"shape": { "small": 8, "medium": 16, "large": 20 }
```

| 键 | 作用于 |
|---|---|
| `small` | 引用竖线、行内填充、导入错误提示。 |
| `medium` | 卡片、代码块、表格、图片、皮肤缩略图。 |
| `large` | 对话框、菜单、底部面板。 |

三个都取小值会得到接近 WPS 的方正感；调大则接近 `Paper` 的柔和外观。

## 部件规范

- **卡片**使用 `surface`，加 1 dp 的 `border` 细线，没有阴影。深色皮肤上阴影本就看不见，
  这正是表面层级和细线存在的原因。请让 `border` 同时能与 `canvas` 和 `surface` 区分开。
- **底部导航栏与侧边导航栏**使用 `surface`，选中项底色为 `accentSubtle`，图标为 `accent`。
  两者同一时刻只会出现一个；窗口宽度达到 640 dp 时会切换为侧边栏。
- **代码块**使用 `codeBackground` 加 `border` 细线。它横向滚动而不换行，所以 `code`
  在小字号下也必须能在 `codeBackground` 上看清。
- **表格**位于 `surface` 之上，外框为 `tableBorder`，表头行为 `tableHeader`。请保证
  `tableBorder` 在 `tableHeader` 上仍然可见，否则表头就不再像独立的一行。
- **引用块**由 3 dp 的 `quoteBar` 和旁边的 `quoteText` 组成。不要让 `quoteBar` 太安静：
  Discord 自己配色中对应的灰色在聊天背景上只有 1.57:1，作为结构提示已经失效。
- **链接**除了颜色还带下划线，所以颜色从来不是唯一的信号。

## 完整文件

MdView 会读取的全部键。请把它当作参考而非起点 —— 设置 `base` 再覆盖十来个令牌的皮肤
更好维护，也更能平稳跨过后续版本。

```json
{
  "schema": 1,
  "id": "solar-flare",
  "name": "Solar Flare",
  "author": "you@example.com",
  "dark": true,
  "base": "ink",

  "colors": {
    "canvas":        "#0E0F13",
    "surface":       "#15171C",
    "surfaceRaised": "#1C1F26",
    "surfaceSunken": "#090A0C",

    "accent":        "#C79BFF",
    "onAccent":      "#1A0B26",
    "accentSubtle":  "#2A1F3D",

    "textPrimary":   "#E9E7F0",
    "textSecondary": "#B4B0C2",
    "textMuted":     "#8B8799",

    "border":        "#282B33",
    "divider":       "#1E212A",

    "link":          "#C79BFF",
    "linkPressed":   "#DCC2FF",

    "code":          "#E4A8CE",
    "codeBackground": "#171A20",

    "quoteBar":      "#C79BFF",
    "quoteText":     "#B4B0C2",

    "tableHeader":   "#171A20",
    "tableBorder":   "#343B47",

    "danger":        "#FF8A80",
    "success":       "#43C08A",
    "selection":     "#3B2A55"
  },

  "shape": { "small": 8, "medium": 16, "large": 20 },

  "type": {
    "bodyScale": 1.0,
    "monoScale": 0.9,
    "headingWeight": 700,
    "tracking": 0.0
  }
}
```

### 顶层键

| 键 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `[a-z0-9][a-z0-9-]{0,63}`。会成为文件名。大写会被折叠为小写；超出字符集则拒绝。不能与内置皮肤的 id 相同。 |
| `name` | 是 | 选择器中显示的名称。会去除首尾空白，并截断到 48 个字符。 |
| `author` | 否 | 目前不在任何界面显示；保留它是为了让文件能带上来源信息。 |
| `dark` | 否 | 是否为深色皮肤，决定它出现在哪一个选择器中。未填写时从 `base` 继承。 |
| `base` | 否 | 用于继承所有未指定令牌的内置皮肤。`dark` 为 true 时默认 `ink`，否则默认 `paper`。 |
| `schema` | 否 | 目前为 `1`。更高的数字仍可解析。 |

可用作 `base` 的内置 id：`paper`、`cobalt`、`sepia`、`solarized-light`、
`ink`、`midnight`、`nord`、`solarized-dark`。

### 颜色格式

`#RGB`、`#RRGGBB` 和 `#AARRGGBB`，大小写均可。`#` 必须保留。`#F0A` 会展开为 `#FF00AA`。
接受透明度，但请三思：半透明令牌会与其后方的内容混合，使它的对比度变得无法预料。

## 出错时会发生什么

MdView 自始至终遵循一条规则：**一个坏值只应该让你失去这个值，而不是整个文件。**

| 情况 | 结果 |
|---|---|
| 未知的顶层键 | 忽略。皮肤被保存时会丢弃。 |
| `colors`、`shape` 或 `type` 中的未知令牌 | 忽略。 |
| 颜色格式错误（`"#GGG"`、`"red"`、`42`） | 该令牌回退到 `base`，同级的其他令牌照常生效。 |
| 数值超出范围 | 收敛到文档给出的范围。 |
| `schema` 大于 1 | 照常解析。 |
| 任何位置出现数组 | 解析后丢弃，这样未来的格式不会让当前版本失败。 |
| 文件开头有字节顺序标记 | 去除。Windows 编辑器常会加上。 |
| `id` 缺失或不可用 | **拒绝** —— *"皮肤的 id 缺失或不可用"*。 |
| 缺少 `name` | **拒绝** —— *"皮肤没有名称"*。 |
| `base` 未知 | **拒绝** —— *"皮肤所基于的皮肤在本应用中不存在"*。 |
| `id` 与内置皮肤重名 | **拒绝** —— *"内置皮肤已占用该 id"*。 |
| 不是 JSON —— 多余逗号、单引号、未加引号的键、注释、`NaN` | **拒绝** —— *"该文件不是本应用能读取的皮肤"*。 |

重新导入一个 `id` 已存在的皮肤会**替换**它 —— 这正是你反复调试自己文件时想要的行为。

### 限制

| 限制 | 数值 |
|---|---|
| 文件大小 | 64 KiB |
| 嵌套深度 | 8 |
| 文件中的值 | 1024 |
| 单个字符串 | 256 个字符 |
| `id` 长度 | 64 |
| `name` 长度 | 48 |
| 保留的导入皮肤数 | 24 |

## 对比度

内置皮肤由**自动化测试**守住下列底线，且是针对全部四个表面层级测量，而不只是其中一个。
请用同样的标准要求你自己的皮肤：

| 前景 | 相对于 | 最低值 |
|---|---|---|
| `textPrimary`、`textSecondary`、`quoteText`、`link`、`linkPressed` | 每一个表面层级 | 4.5:1 |
| `textMuted`、`danger`、`success` | 每一个表面层级 | 3:1 |
| 作为文字的 `accent` | `canvas` 与 `surface` | 3:1 |
| `onAccent` | `accent` | 4.5:1 |
| `code` | `codeBackground` | 4.5:1 |
| `border` | `canvas` 与 `surface` | 1.2:1 |

### 你喜欢的配色多半是不达标的

内置皮肤中有三个偏离了它们的经典取值，因为那些配色是为终端设计的，而终端并不需要通过 WCAG。
这很正常，在移植之前值得先知道：

- **Nord。** Aurora 红 `#BF616A` 在 Nord 自己的 surface 上只有 **2.46:1**，MdView 改用
  `#D9848D`。Frost `#8FBCBB` 作为链接在抬升层上降到 4.14:1，因此链接改用 `#A3CFCE`。
- **Solarized。** 蓝色 `#268BD2` 配白字只有 **3.68:1**。浅色皮肤改用 `#186FA8`，
  深色皮肤则用 `#3AA0E0` 搭配深色的 `onAccent`。
- **Discord。** Blurple `#5865F2` 在自身 surface 上仅 3.37:1，所以它从不作为*文字*使用，
  只作为填充、上面压 `onAccent`，此时为 4.61:1。

## 安装与移除

通过 **我的 → 导入皮肤…** 选择 `.json` 文件导入。各家文件提供方经常把 `.json` 的类型标错，
所以选择器的过滤条件刻意放宽，真正做校验的是文件本身。

导入的皮肤保存在应用私有存储中，并会被**完整重新编码**（不含 `base`），
这样即使后续版本调整了某个内置皮肤，你的皮肤外观也绝不会被悄悄改变。

点皮肤缩略图上的 **×** 可以移除。内置皮肤根本没有 ×。移除正在使用的皮肤会回退到 Paper 或 Ink。

皮肤**不**纳入设备备份，原因和草稿一样：应用私有存储会被还原到另一个应用实例，
其中保存的 URI 授权已经失去意义。

## 有一样东西不受皮肤控制

**Material You（壁纸取色）。** 开启 *使用壁纸颜色* 时，壁纸优先，两个皮肤选择器都会变暗 ——
文档相关的令牌也会依据壁纸配色重建，这样代码块和表格才会一起跟随。想选皮肤请先关掉它。
正是出于这个原因，它默认是关闭的。
